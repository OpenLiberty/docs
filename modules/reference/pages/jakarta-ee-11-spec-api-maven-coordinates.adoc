= Jakarta EE 11 — Complete Specification API Maven Coordinates

Jakarta EE 11 is a landmark release that modernizes enterprise Java for the cloud-native era.
It aligns with *Java SE 17* and *Java SE 21*, removes all remaining optional specifications, introduces the brand-new *Jakarta Data* specification, and cleans up years of accumulated legacy — including the removal of `SecurityManager` references in line with JEP 411.

Whether you are migrating from Jakarta EE 10, building a new application on https://openliberty.io[Open Liberty], or just updating your `pom.xml` — this document gives you every specification API Maven coordinate in one place, organized by profile.


== Key Highlights in Jakarta EE 11

* *Jakarta Data 1.0* — brand-new specification for repository-based data access
* *Jakarta Persistence 3.2* — `java.time` mapping, Records as embeddables, new JPQL functions
* *Jakarta CDI 4.1* — brings important architectural improvements and new APIs to help framework developers build on CDI.
* *Jakarta Faces 4.1* — aligns with CDI where possible, and provides various small enhancements and clarifications.
* *Jakarta REST 4.0* — improved programmatic API
* *Java SE 17 and 21 baseline* — virtual threads, records, sealed classes all first-class
* *All optional specifications removed* — cleaner, leaner platform
* *SecurityManager removed* — aligned with JEP 411


== Quickstart — Use the Jakarta EE 11 BOM

Instead of declaring each API individually, import the platform BOM and omit versions:

[source,xml]
----
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>jakarta.platform</groupId>
      <artifactId>jakarta.jakartaee-bom</artifactId>
      <version>11.0.0</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>
----

Or use `jakarta.platform:jakarta.jakartaee-api:11.0.0` (full platform all-in-one), `jakarta.platform:jakarta.jakartaee-web-api:11.0.0` (Web Profile), or `jakarta.platform:jakarta.jakartaee-core-api:11.0.0` (Core Profile).

Jakarta EE 11 represents the most significant modernization of the platform in years.
The new Java SE 17 baseline unlocks records and sealed classes for enterprise applications — and the removal of optional specifications makes the platform simpler to reason about and implement.

https://openliberty.io[Open Liberty] ships full Jakarta EE 11 support — look for the `jakartaee-11.0` convenience feature in your `server.xml`, or enable individual features like feature:persistence-3.2[], feature:restfulWS-4.0[], and feature:data-1.0[] as needed.

For full specification details, see https://jakarta.ee/release/11/[Jakarta EE 11 website].

For a deep dive into Jakarta EE 11 features and code examples on Open Liberty, see the https://openliberty.io/blog/2026/05/27/Jakarta-EE-11-in-Open-Liberty.html[Jakarta EE 11 from Newbie to Pro with Open Liberty] blog post.
